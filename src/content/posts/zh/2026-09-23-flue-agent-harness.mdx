<Section id="backdrop">
  <SectionHead
    kicker="01 · THE BACKDROP"
    title="前因：从「裸调 API」到「harness 即框架」"
    lead="Flue 在 README 里自己讲了三代智能体的演进史。"
  />
  <Prose>

**第一代：裸 LLM 调用。** 直接发 HTTP 请求给模型 API，拿到文本回复。它只适合简单聊天机器人和写死的脚本流程——模型没有上下文管理、没有工具、没有环境。

**第二代：真正的智能体。** Claude Code、Codex 这一代产品打破了模具：你给的是**目标**而不是预定义步骤，信任智能体在你提供的上下文与工具范围内自主完成任务。但这套「外壳」能力——会话、上下文、工具、技能、文件系统、安全沙箱——长期被锁在各家产品内部，开发者想构建自己的同类智能体，只能从零缝。

**第三代：可编程的 harness。** Flue 的定位就是把这层外壳变成可 import 的 TypeScript 库。它的口号很直接：「Not another SDK. Build autonomous agents with Flue's programmable TypeScript harness.」它的出身值得一提：由 [Astro](https://astro.build) 团队（以 Web 框架著称）开源，工程口味明显偏前端——文件约定优先、Vite 插件构建、函数式组合，而不是企业 Java 式的重型配置。

  </Prose>
</Section>

<Section alt id="model">
  <SectionHead
    kicker="02 · THE MENTAL MODEL"
    title="理解它的核心：智能体就是一个函数"
    lead="这是 Flue 最有辨识度的设计——不是写配置文件，而是写一个带 'use agent' 指令的函数。"
  />
  <Prose>

官方定义里，智能体由三部分组成：**LLM、harness、专用上下文**。Flue 提供两个核心原语把三者组合起来：Agent Functions 与 Agent Hooks。一个最简智能体长这样（摘自官方 README）：

  </Prose>

  <div class="article-prose !mt-0">

```ts
'use agent';
import { useModel, useSandbox, useSkill, useTool } from '@flue/runtime';
import { local } from '@flue/runtime/node';

export function Triage() {
  useModel('anthropic/claude-sonnet-4-6');
  useSandbox(local());
  useSkill(triage);
  useTool(openIssue);
  useTool(searchCode);

  return `Triage a bug report end-to-end: reproduce,
diagnose, verify, and attempt a fix.`;
}
```

  </div>

  <Prose>

函数的返回值是给模型的指令（instruction），而 `use*` 系列调用在运行时把模型、沙箱、技能与类型化工具「装」进这个智能体。这种设计的直接好处是：**整个 harness 都享受 TypeScript 的类型检查、Vite 的构建与任意环境的部署**，而不是被困在某个私有 DSL 里。你换模型、换沙箱、增删工具，就是改几行代码。

  </Prose>
</Section>

<Section alt id="durable">
  <SectionHead
    kicker="04 · DURABILITY"
    title="持久化契约：一旦接纳，就欠你一个终态"
    lead="云端智能体会崩溃、重启、被重新部署。Flue 把「已接纳的工作」做成了显式承诺。"
  />
  <Prose>

官方对 durability 的定义值得逐字理解：**一旦输入被接纳（admitted），运行时就欠这个会话一个持久化的终态（durable terminal outcome）——无论进程崩溃、重启还是重新部署。** 任何到达智能体的输入（HTTP prompt、dispatch 调用、通道消息、定时触发）都先作为一条 submission 被持久化记录，**然后**才开始任何模型工作。接纳记录就是崩溃恢复的起点：中断后重放已接纳但未完成的工作，已完成的持久工具与委派任务不重复执行。

这与消息队列里「至少一次投递 + 幂等消费」是同一套工程思想，只是用在了智能体循环上。官方也诚实地列出了「什么不持久」——并非所有中间状态都被保存。

  </Prose>
</Section>

OpenComputer 的架构文档展示了「零代码智能体」的最简形态：一个 `agent.toml`（名字、模型、运行时家族）加一个 `prompt.md`，加 `skills/` 目录，就能部署成一个边缘 Worker。上限是 prompt 256KiB、最多 32 个打包技能、合计 2MiB。需要自定义工具时再加 package.json 与 flue.config 升级为完整应用——身份与会话历史不丢。这个「prompt 起步、代码毕业」的平滑路径，是 Astro 式 DX（开发者体验）在智能体领域的直接投射。

  </Prose>
