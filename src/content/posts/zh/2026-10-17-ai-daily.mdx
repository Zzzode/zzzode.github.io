<Section canvas id="beam-deployment">
  <SectionHead index="05" kicker="模型接入" title="Beam 的激活参数，不能当作整套权重的内存账单" />
  <Prose tile>

Reflection 在 [10 月 5 日的原始介绍](https://reflection.ai/blog/introducing-beam) 中已经公布 Beam。本窗口发生的更新是 [Transformers 5.20.1 接入它](https://github.com/huggingface/transformers/releases/tag/v5.20.1)，以及相应的加载兼容修复。把这两个时间点分开，才能判断今天真正多了什么。

[随该版本发布的文档快照](https://github.com/huggingface/transformers/blob/v5.20.1/docs/source/en/model_doc/beam.md) 给出的整体规模是总参数 501B、每个 token 激活 23B。Beam 使用混合专家结构：前三层采用稠密前馈网络，后续 49 个稀疏层中，每个 token 从 256 个路由专家里选择 8 个。没有被该 token 选中的专家仍属于模型权重，因此不能用 23B 来估算整套权重的存储需求。

文档将 BF16 检查点描述为约 1 TB，并给出跨 8 个设备分片的示例。这是官方部署示例，不是“所有环境必须买八张卡”的硬件结论，也不是本文做过的成本测试。发布说明中对分布式检查点的 Torch 版本限制，同样不能外推为所有旧版 Torch 路径都不再受支持。

<Section canvas id="operating-boundaries">
  <SectionHead index="06" kicker="运行边界" title="权限和路径参数，需要写进回归用例" />
  <Prose tile>

[Claude Code 的更新](https://github.com/anthropics/claude-code/releases/tag/v2.1.302) 对第三方提供商的默认权限有明确适用条件。原来没有显式指定权限模式的脚本，升级后应重新检查启动参数；显式的 auto 选项仍保留。这里讨论的是工具的启动行为，业务上的提交、发信或部署权限依然来自任务本身的授权。

MCP 是工具连接协议。本期记录的是客户端对 2026-07-28 协商版本中遗漏字段的兼容修复，不把它描述成今天新发布了一项标准。图片来源超过 128 MB 时被拒绝，也是一个输入边界；它不能证明较小的输入一定安全。

[Deep Agents 的 path 修复](https://github.com/langchain-ai/deepagents/releases/tag/deepagents%3D%3D0.7.28) 和 [LangChain Core 的 extras 修复](https://github.com/langchain-ai/langchain/releases/tag/langchain-core%3D%3D1.6.12) 规模不大，但都涉及调用约定。维护者可以用一个限定子目录的 glob 用例、一个保留起始事件附加字段的流式用例检查升级结果。这是本文的工程建议，并非发布方给出的性能测试结论。
