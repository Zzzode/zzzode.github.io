先界定本文的口径：事实来自 Anthropic 的 [Claude Code 官方文档](https://code.claude.com/docs/en/overview)与 [GitHub 仓库](https://github.com/anthropics/claude-code)（2026-09-23 核对，文档随版本快速迭代，具体字段以最新版为准）；技术源流与竞品判断引自公开发布信息；文中的设计解读是我基于文档的归纳，不代表官方说法。本文不教快捷键，只回答一个问题：**一个被数百万人日常使用的编程智能体，内部由哪些工程机制支撑。**

</Prose>

    title="前因：从代码补全，到终端里的智能体"
    lead="Claude Code 不是凭空出现的，它踩在两代编程助手的经验上。"

  <Prose tile>

**第一代：行内补全。** 2021 年 GitHub Copilot 把语言模型带进编辑器，形态是「光标旁边的灰色幽灵文本」——模型只看当前文件与少量上下文，产出一行或一个函数，人始终是驾驶员。它解决了「写得快」，但没有行动能力。

**第二代：编辑器里的聊天。** ChatGPT 与 Cursor 们把对话框嵌进 IDE：模型能看多文件、能给修改建议，但默认仍然是「顾问」——建议由人审查、粘贴、执行。工具调用是零星的，上下文窗口被当作一次性草稿纸。

**第三代：终端原生的智能体。** 2025 年 2 月，Anthropic 在[发布 Claude 3.7 Sonnet 的同时推出 Claude Code](https://www.anthropic.com/news/claude-3-7-sonnet)：一个住在终端里的 agentic coding tool。它不只是给建议，而是自己读代码库、跑命令、改文件、开分支，把「建议—执行—验证」整条链路走完整。官方对自己的定义很克制：模型负责推理，工具负责行动，而 Claude Code 是「围绕模型提供工具、管理上下文的那一层」，这层东西有个专门的名字——**agentic harness（智能体外壳）**。

理解这个定位，才能看懂它的所有设计：模型可能每几个月换代一次，而 harness 解决的是持久问题——给模型什么上下文、让它碰什么、怎么验证它没有闯祸。

  </Prose>

  <Prose tile>

当你给它一个任务，官方描述的循环是这样的：**收集上下文（gather context）→ 采取行动（take action）→ 验证结果（verify results）**。三个阶段不是流水线，而是互相渗透——问一个问题可能只停在收集；修 bug 会在三阶段间反复多轮；重构则把大量时间花在验证。模型根据上一步工具返回的信息决定下一步，把几十次动作串成链，并在中途自行纠偏。

关键在于：**人也在这个循环里**。你可以随时打断、转向、补充上下文。它自主运行，但不剥夺你的方向盘——这是「agent」与「自动脚本」的分界线。

  </Prose>
</Section>

<Section canvas id="context">
  <SectionHead
    index="04"
    kicker="上下文工程"
    title="上下文工程：这个外壳最硬的功夫"
    lead="智能体的能力上限，往往不取决于模型，而取决于它每一步看到什么。Claude Code 把上下文当作需要管理的稀缺资源。"
  />

  <Prose tile>

一次会话的上下文窗口里装着：系统指令、你的消息、它读过的文件、命令输出、CLAUDE.md、自动记忆、已加载的 Skills，还有终端里**你根本看不到的内容**（工具描述、MCP 工具名等）。随着任务推进，窗口必然被填满，于是有了自动压缩（compaction）：把对话历史总结成结构化摘要。问题随之而来——早期指令可能在压缩中丢失。

官方文档把「压缩后什么活下来」列得很清楚：系统提示与输出风格仍然生效；项目根 CLAUDE.md 与无路径作用域的规则从磁盘**重新注入**；自动记忆重新注入；git 状态重新读取；计划模式写出的 plan 从磁盘重载；带路径的规则和嵌套 CLAUDE.md 在模型再次读到对应文件时重载；而**读过的文件不会复活**。这张表直接指导了使用方式：持久的规则写进 CLAUDE.md，临时的大文件让子智能体去读。

  </Prose>

注意最后一句：**CLAUDE.md 和记忆都是「上下文」，不是「强制配置」**。模型理论上可以违反它们；要做到无论模型怎么想都必须拦截某动作，正确的工具是 PreToolUse Hook（下一节）。这种「软引导与硬约束分层」是整个系统最值得学的治理思想——用最便宜的机制（文本）处理 99% 的情况，只在安全边界上动用强制手段。

<Section canvas id="subagents">
  <SectionHead
    index="05"
    kicker="子智能体"
    title="子智能体：用独立的上下文窗口外包噪声"
    lead="主对话不是什么都该自己干。子智能体是 Claude Code 上下文工程里最精巧的一环。"
  />

  <Prose tile>

官方对子智能体的定义是：**拥有独立上下文窗口、独立系统提示、独立工具权限的专职助手**。当一个支线任务会产生大量你之后不会再引用的搜索结果、日志、文件内容时——比如「调研这个陌生目录怎么实现的」——主智能体就把它派给子智能体。子智能体在自己的窗口里折腾，**只把摘要和一小段元数据返回主对话**，噪声被物理隔离。

  </Prose>

  <CardGrid cols={3}>
    <InfoCard surface="white" label="ROUTING" title="靠描述自动委派">
      <p class="mt-2 text-[13px] leading-[1.65] text-muted">

      </p>
    </InfoCard>
    <InfoCard surface="white" label="BUILT-IN" title="Explore 与 Plan 的特权">
      <p class="mt-2 text-[13px] leading-[1.65] text-muted">
        两个内置调研型子智能体会跳过 CLAUDE.md 与 git 状态快照，保持研究轻量省钱；其余子智能体默认加载两者，除非定义里设置 omitClaudeMd。
      </p>
    </InfoCard>
    <InfoCard surface="white" label="COST" title="按任务选模型">
      <p class="mt-2 text-[13px] leading-[1.65] text-muted">
        每个子智能体可以单独指定模型——把机械的搜索、格式化类任务路由给更快更便宜的模型，把架构判断留给旗舰模型，是官方推荐的成本控制手段。
      </p>
    </InfoCard>
  </CardGrid>

  <Prose tile>

会话本身也被当作数据管理：每条消息、工具调用与结果以明文 JSONL 写到 `~/.claude/projects/`，因此支持回退（rewind）、恢复（`--continue` / `--resume`）与分叉（`--fork-session`，复制历史到新会话、原会话不动）。配合 git worktree，可以在不同目录里开多个并行会话而互不污染——这把「多智能体协作」从概念落成了目录学问题。

  </Prose>
</Section>

<Section canvas id="governance">
  <SectionHead
    index="06"
    kicker="治理体系"
    title="治理体系：权限、钩子与扩展点的分工"
    lead="一个能自己执行 shell 的智能体，靠什么不闯祸？靠的是分层，而不是一个总开关。"
  />

  <Prose tile>

先看**设置的优先级**。Claude Code 从多个位置读 settings.json（用户级、项目级、企业级、受管策略），大部分键是**合并**而非覆盖——比如项目里允许的命令不会抹掉你个人的配置；而组织/受管设置压过个人设置，命令行参数只对当前会话生效，权限规则另有一套合并语义。这意味着团队可以把「禁止碰生产目录」之类的硬规矩放在企业层，开发者本地再叠加个人偏好，双方不用互相改文件。

  </Prose>

  <div class="mt-8">
    <BlockTitle title="四个扩展点解决四类问题" />
    <Steps
    tile
          steps={[
        { title: "Skills：可复用的工作流", body: "SKILL.md 用 frontmatter（name/description）声明、正文给指令；Reference 类内容内联进上下文，Task 类（部署、提交流程）可放在独立子智能体里运行（context: fork）。加载后持续占用 token，所以正文要短。" },
        { title: "Hooks：生命周期上的硬约束", body: "用户定义的 shell/HTTP/MCP/LLM/子智能体钩子，在 SessionStart、UserPromptSubmit、PreToolUse、PostToolUse、Stop 等固定时机触发；PreToolUse 可以直接否决一次工具调用——这才是强制力。" },
        { title: "MCP：接外部世界", body: "把外部服务的工具和资源接进智能体，工具名在启动时就进上下文，所以接得越多启动越重。" },
        { title: "Subagents：隔离上下文的外包", body: "高噪声支线任务、需要限定工具集或更便宜模型的工作，派给独立窗口。" },
      ]}
    />
  </div>

  <Prose tile>

Hooks 的触发时机覆盖三种节奏：每会话（SessionStart/End）、每轮对话（UserPromptSubmit/Stop）、以及循环内每次工具调用（PreToolUse/PostToolUse）。同一份钩子配置在终端、IDE、桌面、云端会话里行为一致。此外它还兼容 AGENTS.md：如果仓库已经为别的编程智能体写了 AGENTS.md，Claude Code 可以直接读，或与 CLAUDE.md 同时读——规则不被厂商锁定。

  </Prose>
</Section>
