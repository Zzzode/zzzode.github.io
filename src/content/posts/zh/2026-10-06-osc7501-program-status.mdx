<Prose tile>

你在终端里跑了个 `terraform apply`，切去写代码。二十分钟后想起来：它跑完了吗？还是卡在等你输 `yes`？标签页上什么都没写，你只能切回去看。

这种事每天发生很多次。终端是个哑设备：程序写什么它显示什么，它不知道哪些字节是「在编译」，哪些是「在等密码」。标签页、任务栏、通知系统全都拿不到状态，你只能自己记着、自己回去看。编程助手把这个问题放大了：Claude Code 跑一个任务，中间可能问你好几次权限，一跑几十分钟，你不可能一直盯着。

2026 年 10 月 6 日，Mitchell Hashimoto 给这个问题交了个答案：OSC 7501。他是 Vagrant 的作者、HashiCorp 的联合创始人，这两年在做终端模拟器 Ghostty 和 agent 工具 Rex。协议只有一页：程序往终端写一串转义序列，说清楚自己在忙、在等、还是完了，终端自己决定怎么显示。

</Prose>

<Section canvas id="problem">
  <SectionHead index="01" kicker="问题" title="终端只能猜" lead="两条老路都有硬伤。" />
  <Prose tile>

第一条路是猜。Herdr 这类工具帮你盯多个终端，办法是读屏幕内容和窗口标题，用正则判断程序在干嘛。Hashimoto 在文章里给了个数字：光是识别 Claude Code 这一个程序的检测规则，三个月里改了十次。Claude Code 标题里的 spinner 图案一换，正则就失效。猜屏幕这条路，是在跟所有程序的界面改版打地鼠。

第二条路是让程序直接说。Herdr 和 `cmux notify` 开了本地 socket，程序把状态报过去。准，但每个程序要单独对接每个收件箱；而且本地 socket 过不了 SSH、进不了容器。你 ssh 到一台机器上跑 agent，状态报不回你笔记本上的终端。

Hashimoto 的出发点很简单：程序自己当然知道自己在干嘛，缺的只是一条通道。这条通道本来就存在。终端和程序之间有一条双向连接（pty），你的键盘输入走进去，程序的输出走出来，SSH、容器、tmux 全都透明穿过。要做的只是往输出里混一种终端能看懂的新信号。

<Section canvas id="protocol">
  <SectionHead index="02" kicker="协议" title="一页纸，一个例子看完" lead="先说 OSC 是什么，再用 brew upgrade 走一遍。" />
  <Prose tile>

终端的字节流里能混一种叫转义序列的东西：程序写一串以 ESC 开头的字节，终端不显示它，而是照做。改窗口标题、改文字颜色、移动光标，靠的都是它。这些序列你每天都在用，只是看不见。OSC（Operating System Command）是其中一类，专门干「程序跟终端说句话」这种事，编号各家自己申请。7501 是 Hashimoto 申请的新号，语义是：这条序列里装的是我的状态。

序列长这样：`ESC ] 7501 ;` 开头，`ESC \` 收尾，中间是冒号分隔的 key=value 对。`state` 必填，其余可选。`msg` 是给人看的一句话，用 base64 编码，免得里面的字符把序列弄断。

用 `brew upgrade` 走一遍。它一共发三条报告：

</Prose>
  <div class="not-prose rounded-[18px] bg-white p-6 md:p-8">
    <pre class="overflow-x-auto font-mono text-[12.5px] leading-[1.8] text-ink-2"><code>{`ESC ] 7501 ; state=working:app=brew:msg=SW5zdGFsbGluZyB1cGRhdGVz ESC \\
  → msg 解码：Installing updates

ESC ] 7501 ; state=blocked:kind=auth:app=brew:msg=UGFzc3dvcmQgcmVxdWlyZWQ= ESC \\
  → state=blocked + kind=auth：等密码；msg 解码：Password required

ESC ] 7501 ; state=done:app=brew:msg=VXBncmFkZWQgMTIgcGFja2FnZXM= ESC \\
  → msg 解码：Upgraded 12 packages`}</code></pre>
  </div>
  <Prose tile>

三条分别说「在装更新」「等密码」「升完了 12 个包」。终端收到后怎么显示是它的自由。Rex 的做法：标签页上，在跑就给 spinner，阻塞给黄色标记，完成给对勾；你在别的窗口，它还能发个通知。

发报告有多简单？规范里给了个 rsync 的例子，六行 shell：

</Prose>
  <div class="not-prose rounded-[18px] bg-white p-6 md:p-8">
    <pre class="overflow-x-auto font-mono text-[12.5px] leading-[1.8] text-ink-2"><code>{`status() {
  printf '\\e]7501;state=%s:msg=%s\\e\\\\' "$1" "$(printf '%s' "$2" | base64 | tr -d '\\n')"
}
status working "Syncing photos"
rsync -a ~/Photos backup:/photos && status done "Photos synced" || status error "rsync failed"`}</code></pre>
  </div>
  <Prose tile>

没有 SDK，没有依赖，任何能往 stdout 写字的程序都能发。Hashimoto 给 Terraform、Claude Code、Codex、Homebrew 做了四个概念验证集成，按他的说法，每个都不超过十二行。

</Prose>

<Section canvas id="design">
  <SectionHead index="04" kicker="设计" title="几个值得讲的取舍" lead="协议小，讲究都在为什么这么设计。" />
  <Prose tile>

五个状态里最值得讲的是它们的「死法」。`working` 和 `blocked` 是瞬时状态：进程都退出了，「正在编译」就是谎话，所以规范要求终端在进程退出、或 shell 打出新提示符（OSC 133 的 A）时把它们扔掉。`done` 和 `error` 是结论：你去倒了杯水，回来要看到「升了 12 个包」，所以这两种在退出和新提示符之后都活下来，一直挂到你回来看。协议没有心跳，终端不能靠「好久没刷新」猜程序死了——进程退出和 shell 提示符这两个信号本来就存在，直接复用。

`blocked` 单独带一个 `kind` 键，三个取值：`permission`（等批准）、`question`（等回答）、`auth`（等密码）。分开是因为终端的应对完全不同：等批准可以给个按钮，等密码得弹输入框。状态集合是封闭的：`state` 的值不认识，整条报告丢弃。这样将来加第六个状态，老终端不会把它误读成 idle。

一个程序可能同时跑多件事。部署工具 deploy 在根记录上报 working，下面挂两个子记录：us-east 推镜像到 40%，eu-west 等批准。id 用斜杠分层，`app` 名从祖先继承。根在干活、某个子任务在等批准，两种状态同时成立，终端自己决定显示哪个。每条报告整体替换它那条记录，不做合并。简单，代价是 `app` 这种键每次都得重发。

OSC 7501 的判断是：把「程序现在是什么状态」做成终端持有的一等数据，程序只负责更新，显示完全交给终端。对 OSC 9;4 还有个具体的兼容设计：终端可以把收到的 OSC 9;4 映射到根记录上，但一旦真正的 OSC 7501 报告到达，就应该停止映射，直到下次完全复位。因为 OSC 7501 的报告是整条替换，一条映射过来的 OSC 9;4 会把真实报告里的 `kind` 和 `msg` 抹掉。

</Prose>
</Section>

<Section canvas id="limits">
  <SectionHead index="06" kicker="边界" title="不信任任何输入" lead="规范的原话：报告里的一切，都来自一个已经控制了屏幕的程序。" />
  <Prose tile>

所以 `msg` 和 `title` 不许含控制字符，不许当标记语言解析；终端往外写的字节只有探测回复那固定的几个，记录不可读回。程序可以拼命刷状态，终端应该对通知、声音这类外部效果做限流。超限是整条丢弃，不截断：整条序列 4096 字节（合法报告实际不到 3300），`msg` 解码后 2048，记录每终端 256 条（规范要求至少支持 64）。程序不会面对「发了一半」的中间状态。

协议也有管不着的地方。它只定义了程序到终端这一个方向，终端之间、终端到云端的同步不在范围内；呈现完全交给终端，所以同一个 blocked 状态，在 Ghostty 和 Rex 里长得不一样。这些是有意的留白，不是缺陷。

</Prose>
  <div class="mt-5">
    <Callout tone="insight" eyebrow="WHAT IT DOESN'T DO">
      协议不传输终端的任何数据回程序，记录不可读回；不定义终端之间的同步；不规定呈现样式。它只管一件事：程序把状态说清楚。
    </Callout>
  </div>
</Section>
