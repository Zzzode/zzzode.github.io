<Section canvas id="scientific-models">
  <SectionHead index="03" kicker="科学模型" title="实验过程开始进入科学模型的训练材料" />
  <Prose tile>

科学研究需要保存失败的尝试。只给模型一篇论文，它看到的主要是整理后的结果；记录一次实验的目标、操作和观察，才有机会让它学习怎样选择下一步。[Deep Principle 的技术说明](https://blog.deepprinciple.com/introducing-hydrogen-1.0/)把实验室记录和探索轨迹用于 Hydrogen-1.0 后训练，其中也保留失败候选和修正假设。

权重开放让其他研究者能够检查和调整模型。[模型卡](https://huggingface.co/deep-principle/Hydrogen-1.0)同时提醒，演示包含外部工具和特定实验环境，输出需要科学审查。权重许可与训练数据是否公开是两个需要分别核对的问题。本次已读取模型卡和技术说明，但没有下载大体量权重运行测试。

国内模型的产品报道也在向长任务靠近。LongCat-2.5 的正式版上线报道需要与此前预览版区分；SenseNova 6.8 Flash 的报道则展示了办公任务。本文保留相应可用性条件，厂商榜单和单次演示无法替代跨任务复测。

<Section canvas id="agent-records">
  <SectionHead index="04" kicker="会话与审查" title="保存会话与审核改动，解决的是不同问题" />
  <Prose tile>

长时间运行的 Agent 会反复调用模型。[Claude 的 message threads 文档](https://platform.claude.com/docs/en/build-with-claude/message-threads)让后续请求复用服务器暂存的会话，减少重复传输。模型仍需要处理上下文，所以这种接口变化不能直接理解为 token 费用下降。线程是临时状态，应用还要保存自己的历史，以便失效后恢复。

[Sierra 的 Agent Studio 更新](https://sierra.ai/blog/redesigning-agent-studio-around-ghostwriter)关心工作过程怎样留下可审阅的记录。团队在一个会话里查问题、修改流程、运行测试，改动经过审查和合并后才发布。把这些记录放在一起，能让审阅者追查一项修改的原因；它并不保证修改后的 Agent 一定正确。

金融场景还需要明确谁授权 Agent 行动。[香港金管局的 SAGE 公告](https://www.hkma.gov.hk/gb_chi/news-and-media/press-releases/2026/11/20261102-4/)把 Agent 身份及权限验证列为探索方向。允许读取交易资料，与允许实际付款，应在系统里有各自的授权范围。这里是依据公告议题给出的工程解读，具体监管要求仍须看后续文件。
