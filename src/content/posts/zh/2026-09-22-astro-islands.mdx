<Prose>

先说结论：**群岛（Islands）不是一个新框架，而是一种「大部分静态、局部交互」的页面模型。** 服务器先把整页渲染成 HTML 和 CSS，默认剥掉所有客户端 JavaScript；只有带了 `client:*` 指令的 UI 框架组件才会在浏览器里加载脚本、独立「水合」成可交互的小部件。这个术语来自 Jason Miller 对选择性水合（selective hydration）的描述：在服务器渲染的页面里，给高度动态的区域注入占位符，再在客户端把它们各自激活。

</Prose>

<Prose>

打个比方：传统单页应用（SPA）是把整页都做成一台需要通电才能运转的机器；群岛模型则是一本印刷好的杂志，其中夹着几块可以独立通电的小屏幕。杂志本身（文字、布局、链接）在 JavaScript 到达之前就已经完整可读。

</Prose>

<Prose>

水合（hydration）这个词，白话讲就是**给已经画好的静态 DOM「接上神经」**：把事件监听、组件状态和框架逻辑挂到对应元素上。传统 SPA 给整页接神经；群岛只给那几座小岛接。

</Prose>

<Prose>

框架选择也是可选的：Astro 的组件语言是 HTML 的超集，只用 HTML/CSS 就能建站；需要交互时再按需接入 **React、Preact、Svelte、Vue、Solid、HTMX 或 Web Components**，不被任何一个生态绑定。

</Prose>

<Section id="content-layer">
  <SectionHead
    kicker="06 · CONTENT LAYER"
    title="内容层：让静态站点也有类型安全的数据"
    lead="群岛解决「发不发 JS」，内容层解决「内容从哪来、字段靠不靠谱」。"
  />
  <Prose>

Astro 的 Content Layer 把 Markdown/MDX/JSON 等组织成**内容集合（collections）**：一组结构相同的条目（entries），由 `src/content.config.ts` 里的 `defineCollection()` 声明，配合 `glob()` 加载器和可选的 Zod schema。front matter 不符合 schema 时，构建会直接报错，而不是等线上页面出问题；同时自动产出 TypeScript 类型与编辑器补全。

  </Prose>

  <Callout eyebrow="WHEN IT CLICKS">
    群岛 + 内容层组合起来正是内容型网站想要的形态：文章是构建期校验过的静态 HTML，速度与 SEO 默认拉满；评论框、搜索、播放器这类真正需要交互的地方，再用一座岛屿按需通电。
  </Callout>
