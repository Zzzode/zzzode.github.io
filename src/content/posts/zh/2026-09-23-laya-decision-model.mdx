    index="01"
    kicker="判断即分类"
    title="前因：「判断」说到底是分类，分类不用逐词生成"
    lead="理解 Laya 的关键，是先看清决策模型和聊天模型用的根本不是一类网络。"
  />
  <Prose tile>

聊天大模型是**解码器-only（decoder-only）架构**：从左到右一个 token 一个 token 地生成，输出 200 个词就要做 200 次序列计算，这是它慢和贵的根源。而 BERT 一脉的**编码器-only（encoder-only）模型**天生为理解任务设计：输入整段文本，双向注意力一次读完全部上下文，直接在特定位置输出类别分布——垃圾邮件分类、情感分析、自然语言推断都是 BERT 时代的标准任务。

2024 年 12 月，Answer.AI 与 LightOn 等发布 [ModernBERT](https://huggingface.com/blog/modernbert)，把这条老路线现代化：base 149M、large 395M 参数，原生 8192 上下文，RoPE 位置编码、交替局部/全局注意力等新架构，处理速度远快于老 BERT，官方定位是「BERT 的直接插槽替代」。Laya 做的事，就是在这个现代化编码器上接一个**决策头（decision head）**，把「带类型的问题」变成一种请求时才定义答案空间的分类任务。作者在 dev.to 长文中提到，他早在 Jev 发布约一年前就在做非自回归决策模型——同一思想在开源与闭源两侧独立汇流。

  </Prose>

<Section canvas id="rlcd">
  <SectionHead
    index="03"
    kicker="训练方法"
    title="训练：用 proper scoring rule 逼模型不敢撒谎"
    lead="Laya 的 RLCD 给出了「校准」在数学上怎么落地：当且仅当报告真实概率时，期望奖励最大。"
  />
  <Prose tile>

模型卡对训练方法的披露相当具体，值得逐条讲。策略网络输出一个概率分布，探索时在 logits 上加零均值高斯噪声；奖励函数是**严格适当评分规则（strictly proper scoring rule）的组合**——log score 加 spherical score，有序的 score 问题再加 ranked probability score（排位概率分，专门惩罚把概率放错序位）。这类规则的数学性质是：**只有如实报告自己的真实信念分布，期望奖励才能最大化**——系统性地过度自信或不自信都会被扣分。优化用 REINFORCE 加组均值基线，模型卡明确标注「GRPO-style」，多轮对话则在对话前缀切片上做 TD(λ=1.0)。这与本博客 MiMo 一文里 GRPO 的训练骨架同源，区别全在奖励函数的形状：可验证答案 vs 校准概率。

这里也能看出开源与闭源叙事的一个有趣对照：TypeSafe 把 RLCD 作为自己提出的训练路线名称（并强调 RLHF 共同发明人在创始团队）；Laya 的模型卡直接采用同一术语描述自己的训练，把它具体化成一组可复现的评分规则与超参配方。

  </Prose>
</Section>

Router 的存在来自一个真实的、模型卡主动披露的惨痛发现：**英文检查点在非拉丁文字上不是「不知道」，而是「自信地错」**——高棉语（Khmer）测试集上准确率 0.000，置信度却高达 0.952。这种状态下，Jev/Laya 架构里最核心的「低置信就上报」闸门完全失效：模型没有给你升级的机会。Router 的对策是在**前向计算之前**用纯 Python 做亚毫秒级的文字脚本检测（高棉文 100% 非拉丁字母 → 英文模型读不了），直接路由到多语言检查点，而不是指望模型自己谦虚。

部署上还有一个开源模型特有的坑，模型卡也写得很明白：懒加载默认只驻留一个检查点，混合语言流量每次切换都要重新装载权重——CPU 中位 7.4 秒、T4 上 10.3 秒。生产环境必须 `Router(preload=True)`：预载后语言切换只剩亚毫秒检测，GPU 单问 32.8 毫秒，CPU 193–464 毫秒。

  </Prose>
</Section>

    title="真正的教训：置信度不是安全保证"
    lead="Laya 模型卡最有价值的部分，不是基准成绩，而是它把失败模式写在了使用说明第一页。"

  <Prose tile>

把 Jev 与 Laya 两篇连起来看，System 1 决策模型这类系统的工程常识已经浮现：**校准是群体统计性质，而自动化闸门面对的是每一个具体样本。** 高棉语 0.000 准确率配 0.952 置信度、英文模型在域外语言上「自信地错」、DAIR Emotion 上 16% 的真标签被赋予零概率——这些都说明同一件事：在分布偏移（语言不符、标签太多、领域陌生）面前，置信度门限会静默失效。JEV-as-a-Judge 论文从另一侧给出同一个答案的补丁：高置信自动采纳、低置信升级给强模型的级联，前提是置信度本身在你的任务分布上被校准过。

因此引入任何决策模型的正确姿势都一样：先用自己的数据复测校准曲线，为域外输入（语言、长度、标签基数）准备**模型之外的确定性探测器**（Router 的脚本检测就是范例），再把「执行/上报」闸门建立在多层信号而非单一置信度上。判断模型让 Agent 更快更便宜，但「何时可以信任它」这个判断，仍然是人的工程责任。

  </Prose>
