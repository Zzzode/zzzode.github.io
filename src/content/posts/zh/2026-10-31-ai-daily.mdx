<Section canvas id="agent-tools">
  <SectionHead index="04" kicker="工具更新" title="从界面生成到本地执行，接口正确仍需要运行时检查" />
  <Prose tile>

[A2UI CLI 的首次版本](https://github.com/a2ui-project/a2ui/releases/tag/cli-v0.1.0)把组件目录转成带类型的 Python 构建器。组件目录描述界面能用什么组件、接受什么字段；生成代码可以让开发者更早发现字段拼写和结构错误。这次发布涉及多个协议版本，团队需要让目录版本与消费界面的一端一致，不能把代码生成器的发布当成所有客户端都已兼容。

[Laya 0.4.18](https://github.com/NandhaKishorM/laya/releases/tag/v0.4.18)的更新发生在另一处：本地 C++ ONNX 后端、可选择开启的 MCP 路由诊断，以及输入格式异常时的拒绝处理。ONNX 是模型交换与运行格式，后端支持本身不能证明具体模型在每台机器上的速度或正确率。这里明确指向已链接的 NandhaKishorM/laya 开源项目，不把其他同名项目视为同一产品。

这两类工具都在减少接入中的歧义。但类型检查不会自动授予权限，诊断开关也不能代替执行前的授权。工程上仍要检查实际版本、允许访问的资源及失败后的行为。本期没有复现工具的全部功能或独立性能测试。

  </Prose>
</Section>

<Section canvas id="training-controls">
  <SectionHead index="05" kicker="训练授权" title="网站表达训练意愿，与法院判断使用是否合法，是两件事" />
  <Prose tile>

[Google 的新公告](https://developers.google.com/search/blog/2026/10/ai-training-control)讨论在 robots.txt 中使用共同的训练控制标记，让网站不必逐个配置不同爬虫。Google 计划在 2027 年支持这一机制，所依据的 IETF AIPREF 工作仍是草案。Google-Extended 等专用设置仍会与共享信号并存，需要核对具体优先规则。不能把计划写成已经运行的统一标准，也不能推导出网站声明必然得到所有使用者遵守。

[Wikimedia 的法庭之友意见](https://wikimediafoundation.org/news/2026/10/30/wikimedia-foundation-amicus-brief-new-york-times-v-open-ai-case/)区分模型训练与检索增强生成中的内容使用。检索增强生成，是系统先取回资料再据此回答；取回后怎样展示原文、怎样标注来源，会产生与训练不同的问题。基金会是在表达自身法律立场，这份意见不是法院判决。

[英国 CMA 的调查](https://www.gov.uk/government/news/cma-opens-investigation-into-metas-commercial-terms--2)关注 Meta 商业条款与竞争问题，启动调查不代表认定违法。[DRCF 的联合声明](https://www.drcf.org.uk/publications/joint-statements/joint-statement-on-protecting-people-and-businesses-in-an-agentic-economy)则谈到 Agent 代表消费者行动时的保护。这份声明说明既有法律和监管框架如何适用于个人 Agent，并提出继续协调工作；它不是新法律。这几项进展共同提示：技术上的访问设置、合同条款和监管判断各有范围，不能互相替代。

[AWS 的 GovCloud 配置指南](https://aws.amazon.com/blogs/machine-learning/configure-the-chatgpt-desktop-app-with-amazon-bedrock-in-aws-govcloud-us/)把桌面客户端的推理请求送到指定的 Bedrock 端点，由设备策略和 AWS 身份权限约束使用。此时 ChatGPT 工作区角色并不直接管理这条 AWS 路径。区域、身份和功能限制要一起验证；零数据保留也是可配置模式，不能只换一个地址就宣称合规。

[Bedrock 的 API 与跨区域更新](https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-openai-runtime-govcloud/)使用的是 bedrock-runtime 端点，不能直接套用桌面指南的 Mantle 配置。[Kiro 的网页搜索](https://aws.amazon.com/about-aws/whats-new/2026/10/kiro-web-search-aws-govcloud-us/)则可由企业管理员关闭搜索和抓取。三条接入路径应分别核对能力与访问规则。

安全模型的可用范围同样具体。[Daybreak Red 的 AWS 公告](https://aws.amazon.com/about-aws/whats-new/2026/10/openai-daybreak-red-govcloud-east/)要求客户先取得相关资格，再通过 AWS 开通。它是特定区域的访问扩展，不是面向所有人的新模型首发。

机器人方向，Ludi 0.2 的新展示关注怎样理解人的意图并协调动作。演示系统、公开模型权重和可采购产品是不同阶段；厂商关于社交理解的描述，还不足以证明开放环境中的可靠性。对准备部署的团队，先看可取得的版本和实际约束，再决定是否进入自己的验收流程。
